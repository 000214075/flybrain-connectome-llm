## 三、结论（哪些是实测，哪些是推断）

**实测**：

- 交互链路**完整可用**：FastAPI + SSE 流式 + 浏览器逐字显示，单次回复 0.6–3.1 秒。
- 输出**不是对话**。三种输入、两种系统提示设置下，输出的都是**语料里的"评分/指令模板"片段**（反复出现 `这段资料…关键数字必须与资料一致：`），**两条都在冒号处断掉**，从不给出冒号后面的内容；还混入模板残留（`**`、`- \\(V+t^{...}`、`## 3.`）。
- **去掉系统提示不改变结论**：同一句 `这段资料…数字必须与资料一致：` 在两种设置下都出现 ⇒ 它是**被记住的语料高频句**，不是系统提示造成的。**"配置错误"这一假设已被排除**。
- 模型确实学到了领域词汇与部分结构：`连接组`、`突触`、`PN 输入电流`、`Drosophila melanogaster`、`PMID`、`VNC`、`139,255`（语料中的真实数字）都能正确拼出。

**因此（推断，尚未直接证明）**：问题在**训练状态**，不在服务端。可归因的实测事实是：固定 24 批留出集 **3.6349 / ppl 37.90**；18000 步只覆盖语料 **45.6%**（77.1 MB / 4,039 万 token，远不到一个 epoch）；`context: 32` 极短（对话结构在 32 个 token 里几乎无法表示）；语料本身是文档/指令体，不是对话体。

**对照（本项目自己的历史）**：早期**混合**模型（含 attention，ppl 10.42，仅 400 步）能写出通顺中文。所以"完全基于苍蝇大脑结构、不引入现代 LLM 分支"这条要求，当前在**交互质量上**的代价是可见的。

**尚未验证**：

- 长训练（rank512，18000 步，约 17:14 停）能否把输出推到可读——**这是当前唯一在跑的、可能改变上表的实验**。
- `context` 长度对纯模型从未测过（canonical 用 32，混合模型当年用 512）。
- 未做：把 checkpoint 换成 rank512 新臂后再采样。
- 未做：给定前缀续写（而非问答）——对 base 模型这可能是更公平的评测形式。
